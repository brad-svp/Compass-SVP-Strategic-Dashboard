---
name: SVP planning policy
description: User decisions for current dashboard periods, quarterly direction, personal 6x6 priorities and continuous event timeline
---

QBOs are organization-wide quarterly objectives/results. Each quarter may have an optional administrator-authored narrative setting tone and direction above its QBOs.

6x6 priorities are independent per person, not a shared set of company moments with teammate assignments. **All roles can view everyone's plans.** Staff can edit their own items only; administrators can edit all. Every user can switch between My, All and a multi-selected teammate view, saved to their account across sessions.

A person's 6x6 has six priority boxes, each holding at most one priority—not multiple items in the same box.

**Why:** The user explicitly clarified that only one priority belongs in each box.

**How to apply:** Preserve this limit when creating, assigning or carrying priorities forward; never overwrite or discard existing priorities to make room.

The home dashboard shows the current period automatically, without date filters; users browse other periods within the dedicated sections. Its primary content is **My 6x6 only**, followed by QBOs, with the next 90 days of events and mission content last. Home has one full-width "View all 6x6 priorities" link, not teammate selection controls. My/All/custom saved viewing choices belong on the full 6x6 page. Do not add the removed "Who carries" / "Recent check-ins" summary row back to home.

The calendar timeline opens at today and must allow scrolling backward and forward across year boundaries, rather than silently limiting the timeline to the current year.

Use the name **Master Calendar**. Date TBD events may have an optional planning month; show them within that month as **Day TBD**, never as a fabricated actual day or subscription date. Wix page URLs are legacy data, not current form/detail fields.

The Master Calendar also includes date-specific planning notes, not just events: for example, “FP applications are released” and other notable planning activities.

**Why:** The user requested these alongside events on 2026-11-16 so operational preparation appears on the same calendar.

**How to apply:** Distinguish planning notes from actual events and event attendance/registration metrics, without inventing event times or locations.

**Why:** The user explicitly chose independent personal priorities and asked to separate the current-work dashboard from historical/future navigation. They corrected a misunderstanding: viewing teammates is never restricted to administrators; only editing is role-restricted.

**How to apply:** Preserve these distinctions when changing planning models, dashboard widgets, calendar navigation or MCP explanations. Do not reintroduce shared company priority titles or home date selectors.

All signed-in staff may manage Master Calendar events and planning notes; a shared change log must identify what changed, when and by whom. Program configuration stays administrator-controlled. MCP calendar access remains read-only.

**Why:** The user explicitly expanded calendar editing from administrators to all users while requesting visible accountability for changes.

**How to apply:** Do not restore admin-only event editing when adjusting calendar permissions or confuse web editing with MCP write access.

Only the actual current 6x6 should offer copy-forward to the next period. Keep the original priority; respect the same owner/admin editing boundaries.

**Why:** The user requested a quick carry-forward action specifically from the Current 6x6, not arbitrary historical/future plans.

**How to apply:** Keep this action tied to the period containing today rather than whichever period is currently selected for browsing.
